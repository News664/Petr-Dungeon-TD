# Notes for coding agents

Read `docs/design/handoff/GAME_DESIGN_SPEC.md` and `docs/design/handoff/AGENTS.md` before changing game rules. The files in `docs/design/handoff/` are the original handoff: do not edit them. Decisions made since are in `docs/ASSUMPTIONS.md`; add to it whenever you pick a value or rule the spec leaves open.

## Rules of the codebase

- `src/sim` is the game. It must stay pure: no DOM, no `Date`, no `Math.random` (use `rng.ts`), no imports from `src/app`. A test enforces this.
- All state is plain JSON in `CampaignState`. Change it only through a `Command` handled in `src/sim/commands.ts`. Rule violations call `fail(...)` with a message a player can read.
- The clock moves only in `src/sim/time.ts`, one hour at a time, in a fixed event order. Do not add a second place that advances time.
- Balance numbers and map layouts live in `config/`, never in code.
- Defense battles are part of the simulator (`src/sim/battle.ts`): fixed ticks, no randomness, integer state. The renderer only draws `state.battle` and sends `battle_tick`.
- The labyrinth is part of the simulator too (`src/sim/dungeon.ts`, `src/sim/combat.ts`). Randomness there goes through the seeded generator in the state.
- Presentation (`src/app`) reads state and dispatches commands. It holds no game rules.
- An adventurer's strength (level, skill ranks, gear) is read through `statsOf` in `src/sim/growth.ts`. Do not read class base stats directly in combat or battle code.
- Every statue uses the same 30-day deadline. Do not add location- or structure-specific timers.

## If you are here to make pictures

Read `graphics/AGENT_GUIDE.md` and work only from the `graphics/` folder. Add picture files under `public/art/` and nothing else. Do not change code, configuration, lore or the briefs.

## Other folders

- `graphics/` holds art requirements (agent guide, style guide, briefs, `asset_list.json`). It is documentation: the game reads art only from `public/art/`. `public/art/manifest.json` is generated by `scripts/art-manifest.mjs` and is not committed.
- `content/stories.json` holds the words spoken at story moments. The rules only record ids (`tell` in `src/sim/story.ts`); a test fails if a recorded id has no text.
- `lore/` holds the world and character draft. Statements there are labelled Fixed, Proposed or Open; keep the labels when adding to it, and do not contradict a Fixed statement without changing the rules it comes from.

## Before you commit

```bash
npm run typecheck && npm test && npm run build
```

New rules need a test. The handoff scenarios T01–T14 in `src/sim/__tests__/acceptance.test.ts` must keep passing.
